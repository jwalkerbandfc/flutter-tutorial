The Basics

In Module 1 you got Flutter installed and glanced at a working app without really unpacking it. Now we slow down. By the end of this module you'll understand exactly what runApp() does, the difference between a widget that never changes and one that does, and how to lay out a real screen — all while building the start menu for the game we're working toward.

1. runApp() and the Widget Tree

Everything in Flutter is a widget — text, buttons, spacing, even the whole screen is a widget. Widgets get nested inside other widgets to build up your app, and that nested structure is called the widget tree.

Analogy: think of a widget tree like the layers of a hamburger. The bun on the outside wraps everything — that's your top-level app widget. Inside that, you've got the lettuce, the patty, the cheese, each one sitting inside the layer before it. Change the patty and the rest of the burger doesn't care — it just wraps around whatever you put there. Widgets work the same way: each one just describes itself and wraps around whatever's passed in as its child (or children).

runApp() is the very first thing that runs in a Flutter app. It takes one widget — the root of the whole tree — and tells Flutter "draw this, and everything inside it, onto the screen." Every app you build in this course starts with exactly one call to runApp().

2. StatelessWidget: The Printed Photograph

The simplest kind of widget is a StatelessWidget. It has one job: a build() method that describes what it looks like.

Analogy: a StatelessWidget is like a printed photograph. Once it's printed, it looks exactly the same forever — it doesn't matter what happens in the room around it. If you want a different picture, you have to print a completely new one. That's fine for things that genuinely never change once they're on screen, like a title or a static label.

Example 1: A Game Menu Screen

Let's build the start screen for our game. This uses MaterialApp (which sets up theming and navigation for the whole app) and Scaffold (which gives you the basic page structure — an app bar up top and a body underneath).

New File 
import 'package:flutter/material.dart';

void main() {
  runApp(const GameMenuApp());
}

class GameMenuApp extends StatelessWidget {
  const GameMenuApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Game Menu',
      theme: ThemeData(useMaterial3: true, primarySwatch: Colors.indigo),
      home: const MenuScreen(),
    );
  }
}

class MenuScreen extends StatelessWidget {
  const MenuScreen({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Sky Runner')),
      body: const Center(
        child: Text(
          'Welcome, Player!',
          style: TextStyle(fontSize: 28, fontWeight: FontWeight.bold),
        ),
      ),
    );
  }
}

Notice MenuScreen only has a build() method — no memory, no changing data. It gets built once and just sits there, like our printed photo.

3. Layout Basics: Column, Row, and Container

Right now our menu just centers one line of text. Real screens need proper layout, and Flutter gives you three workhorse widgets for that:

Analogy: imagine a bookshelf. A Column stacks its children top to bottom, like books standing upright next to each other on a shelf. A Row lines its children up side by side, like lying those same books flat in a stack. MainAxisAlignment controls spacing along the direction you're stacking (top-to-bottom for a Column); CrossAxisAlignment controls alignment across it.

A Container is like a picture frame — you can give it padding (space inside the frame), a background color, and rounded corners, and it wraps around whatever child you put inside it. SizedBox is just an invisible spacer, useful for pushing things apart by an exact amount.

Example 2: Adding a Stats Bar

Let's replace that single line of text with a proper layout: a welcome message, and a little card underneath showing the player's lives and score.

import 'package:flutter/material.dart';

void main() {
  runApp(const GameMenuApp());
}

class GameMenuApp extends StatelessWidget {
  const GameMenuApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Game Menu',
      theme: ThemeData(useMaterial3: true, primarySwatch: Colors.indigo),
      home: const MenuScreen(),
    );
  }
}

class MenuScreen extends StatelessWidget {
  const MenuScreen({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Sky Runner')),
      body: Padding(
        padding: const EdgeInsets.all(24.0),
        child: Column(
          mainAxisAlignment: MainAxisAlignment.center,
          crossAxisAlignment: CrossAxisAlignment.center,
          children: [
            const Text(
              'Welcome, Player!',
              style: TextStyle(fontSize: 28, fontWeight: FontWeight.bold),
            ),
            const SizedBox(height: 24),
            Container(
              padding: const EdgeInsets.symmetric(horizontal: 20, vertical: 12),
              decoration: BoxDecoration(
                color: Colors.indigo.shade50,
                borderRadius: BorderRadius.circular(12),
              ),
              child: const Row(
                mainAxisSize: MainAxisSize.min,
                children: [
                  Icon(Icons.favorite, color: Colors.red),
                  SizedBox(width: 8),
                  Text('Lives: 3', style: TextStyle(fontSize: 18)),
                  SizedBox(width: 24),
                  Icon(Icons.star, color: Colors.amber),
                  SizedBox(width: 8),
                  Text('Score: 0', style: TextStyle(fontSize: 18)),
                ],
              ),
            ),
          ],
        ),
      ),
    );
  }
}

We've nested a Row (the lives/score) inside a Container (the card), inside a Column (stacked under the welcome text), inside Padding — a mini widget tree, just like the hamburger from earlier.

4. StatefulWidget: The Whiteboard

Right now the score is stuck at 0 forever, because it's just text — printed once and never redrawn. To let the player actually score points, we need a widget that can remember changing data and redraw itself when that data changes.

Analogy: if a StatelessWidget is a printed photo, a StatefulWidget is a whiteboard. You can rub bits out and write new numbers on it whenever you like, and everyone looking at the whiteboard instantly sees the update. In Flutter, "rubbing out and rewriting" is done by calling a method named setState() — it tells Flutter "some data changed, please redraw."

A StatefulWidget is actually two classes working together: the widget itself (which barely does anything) and a matching State class that holds the data and the real build() method. It looks like more boilerplate than StatelessWidget, and it is — but that's the price of being able to change.

Keep this in mind for later: every frame of a game is really just setState() being called over and over, each time with slightly updated numbers — a player's position moving a few pixels, gravity pulling them down a little more. Module 5's entire game loop is this exact idea, just running automatically many times a second instead of waiting for a tap.

Example 3: Making the Score Interactive

Let's turn MenuScreen into a StatefulWidget and add a button that increases the score each time it's tapped.

Replaces the entire file 
import 'package:flutter/material.dart';

void main() {
  runApp(const GameMenuApp());
}

class GameMenuApp extends StatelessWidget {
  const GameMenuApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Game Menu',
      theme: ThemeData(useMaterial3: true, primarySwatch: Colors.indigo),
      home: const MenuScreen(),
    );
  }
}

class MenuScreen extends StatefulWidget {
  const MenuScreen({super.key});

  @override
  State createState() => _MenuScreenState();
}

class _MenuScreenState extends State {
  int _score = 0;

  void _addPoint() {
    setState(() {
      _score++;
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Sky Runner')),
      body: Padding(
        padding: const EdgeInsets.all(24.0),
        child: Column(
          mainAxisAlignment: MainAxisAlignment.center,
          crossAxisAlignment: CrossAxisAlignment.center,
          children: [
            const Text(
              'Welcome, Player!',
              style: TextStyle(fontSize: 28, fontWeight: FontWeight.bold),
            ),
            const SizedBox(height: 24),
            Container(
              padding: const EdgeInsets.symmetric(horizontal: 20, vertical: 12),
              decoration: BoxDecoration(
                color: Colors.indigo.shade50,
                borderRadius: BorderRadius.circular(12),
              ),
              child: Row(
                mainAxisSize: MainAxisSize.min,
                children: [
                  const Icon(Icons.favorite, color: Colors.red),
                  const SizedBox(width: 8),
                  const Text('Lives: 3', style: TextStyle(fontSize: 18)),
                  const SizedBox(width: 24),
                  const Icon(Icons.star, color: Colors.amber),
                  const SizedBox(width: 8),
                  Text('Score: $_score', style: const TextStyle(fontSize: 18)),
                ],
              ),
            ),
            const SizedBox(height: 32),
            ElevatedButton(
              onPressed: _addPoint,
              child: const Text('Tap to score a point!'),
            ),
          ],
        ),
      ),
    );
  }
}

A few things changed: MenuScreen now extends StatefulWidget instead of StatelessWidget; a new class, _MenuScreenState, holds the actual score as a variable; and an ElevatedButton calls _addPoint() when tapped, which calls setState() to increase the score and redraw.
