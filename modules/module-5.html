The Game Loop

Everything on screen right now is frozen — a nice picture, but not a game. This final module fixes that. We're going to build the loop up one small piece at a time: first just prove it's ticking, then add gravity, then a jump, then an obstacle, then a way to lose. Five small steps, each adding exactly one new idea to the class before it.

1. The Flipbook, For Real This Time

Back in Module 2 we mentioned that a game is really just setState() being called over and over, automatically, many times a second. That's the whole secret. A "game loop" is just something that keeps calling a function on a timer, forever, and each call nudges every entity's position a tiny bit before redrawing.

Analogy: a flipbook only looks like it's moving because you flip through dozens of nearly-identical drawings really fast. Nothing on any single page moves — your eye just can't tell the difference between "the ball moved" and "a new picture with the ball slightly further along" flashed past you fast enough. A game loop does exactly that, automatically, roughly 60 times every second.

2. AnimationController vs. Ticker

You may have seen AnimationController used elsewhere in Flutter — it's great for a single animation with a clear start and end, like a button fading in over 300 milliseconds. But a game doesn't have an end (until you crash). We need something that just keeps firing, indefinitely, with no built-in duration.

Analogy: think of Ticker as a heartbeat, and AnimationController as a stopwatch built on top of that heartbeat. AnimationController uses the heartbeat to count from 0% to 100% of a fixed animation and then stops. We don't want that — we just want the raw heartbeat itself, firing forever, so we can decide what to do with each beat ourselves.

To get a raw Ticker, a State class mixes in SingleTickerProviderStateMixin and calls createTicker(), passing a function that gets called on every single frame. Ticker itself lives in package:flutter/scheduler.dart — that's a separate import from material.dart, so every snippet from here on adds it at the top.

Example 1: The Ticker Heartbeat

Let's build the smallest possible version first: nothing about gravity or players yet, just proof that the loop is alive. We'll convert GameScreen from a StatelessWidget into a StatefulWidget, and have it count how long it's been running.

First, the widget shell — this is the same conversion pattern from Module 2, just with an empty State class for now: 

class GameScreen extends StatefulWidget {
  final GameSession session;

  const GameScreen({super.key, required this.session});

  @override
  State createState() => _GameScreenState();
}

Now add the ticker itself. createTicker() needs a callback — _onTick — that Flutter will call on every frame, passing how much time has elapsed since the ticker started: 

class _GameScreenState extends State
    with SingleTickerProviderStateMixin {
  late final Ticker _ticker;
  Duration _elapsed = Duration.zero;

  @override
  void initState() {
    super.initState();
    _ticker = createTicker(_onTick)..start();
  }

  @override
  void dispose() {
    _ticker.dispose();
    super.dispose();
  }

  void _onTick(Duration elapsed) {
    setState(() {
      _elapsed = elapsed;
    });
  }

initState() runs once, when the screen first appears — that's where we create and start the ticker. dispose() runs once, when the screen closes — forgetting to call _ticker.dispose() there would leave the loop running forever in the background, even after the player's left the screen.

Finally, close the class with a build() that shows the elapsed time — proof, on screen, that _onTick really is firing: 

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Game')),
      body: Center(
        child: Text(
          'Running for ${_elapsed.inSeconds}s',
          style: const TextStyle(fontSize: 28),
        ),
      ),
    );
  }
}

3. Gravity: Speed That Builds Up

Analogy: picture a snowball rolling down a hill. It doesn't instantly hit top speed — every second it rolls, it picks up a bit more speed than it had the second before. Gravity in our game works the same way: every tick, we add a small amount to the player's falling speed, and then move the player down by however fast they're currently falling. The longer they fall, the faster they fall.

Example 2: Player + Gravity

Now let's put that heartbeat to work. We'll bring back the Player entity from Module 4, swap the elapsed-time counter for a fixed 360×520 game viewport (so we have known dimensions to do physics maths against), and write the function that actually moves the player: _updatePhysics().

First, new fields for the viewport size, the gravity constant, and the player — created in initState() alongside the ticker: 

class _GameScreenState extends State
    with SingleTickerProviderStateMixin {
  static const double gameWidth = 360;
  static const double gameHeight = 520;
  static const double gravity = 0.6;

  late final Ticker _ticker;
  late Player _player;
  double _velocityY = 0;

  @override
  void initState() {
    super.initState();
    _player = Player(x: 40, y: 0);
    _ticker = createTicker(_onTick)..start();
  }

  // dispose() is unchanged from Example 1.

Next, replace the old _onTick body. Instead of updating a counter, it now hands off to a new method, _updatePhysics() — separating "a tick happened" from "what a tick actually does" is good practice once that logic grows past one line: 

  void _onTick(Duration elapsed) {
    setState(_updatePhysics);
  }

  void _updatePhysics() {
    _velocityY += gravity;
    _player.y += _velocityY;

    final groundY = gameHeight - _player.size;
    if (_player.y > groundY) {
      _player.y = groundY;
      _velocityY = 0;
    }
  }

That's the whole snowball idea in four lines: _velocityY grows by gravity every tick, the player moves down by however fast they're currently falling, and once they'd go past the ground, we snap them back to groundY and zero out the speed so they come to rest instead of sinking through the floor.

Last, update build() to show the fixed-size viewport with the player and background inside it, instead of the elapsed-time text: 

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Game')),
      body: Center(
        child: SizedBox(
          width: gameWidth,
          height: gameHeight,
          child: ClipRect(
            child: Stack(
              children: [
                const GameBackground(),
                _player.build(),
              ],
            ),
          ),
        ),
      ),
    );
  }
}

4. Jumping: A Sudden Kick

Analogy: gravity builds speed gradually, but a jump is the opposite — an instant burst, like stomping a pogo stick. The moment the player taps the screen, we immediately set their falling speed to a big negative number (upward), and then just let gravity do its normal job of gradually pulling that speed back down to zero and beyond, curving them back to the ground.

Example 3: Tap to Jump

Three small additions this time. First, a ceiling clamp — add this to the bottom of _updatePhysics(), right after the existing ground check, so a big jump can't send the player flying off the top of the screen: 

    if (_player.y < 0) {
      _player.y = 0;
      _velocityY = 0;
    }
  }

Second, the jump itself — a new method that instantly overwrites the falling speed with a big upward number: 

  void _jump() {
    setState(() {
      _velocityY = jumpVelocity;
    });
  }

(That needs one more constant alongside gravity: static const double jumpVelocity = -12;)

Third, wrap the viewport in a GestureDetector in build() so tapping anywhere on it calls _jump: 

      body: Center(
        child: GestureDetector(
          onTap: _jump,
          child: SizedBox(
            width: gameWidth,
            height: gameHeight,
            child: ClipRect(
              child: Stack(
                children: [
                  const GameBackground(),
                  _player.build(),
                ],
              ),
            ),
          ),
        ),
      ),
Adds to Example 2 — jumpVelocity, _jump(), and a GestureDetector

Try tapping repeatedly in the panel above — each tap resets the falling speed to jumpVelocity, and gravity immediately starts curving it back down. That's the entire "feel" of a jump-based game, in about four lines of physics.

5. Bounding-Box Collision: Do Two Boxes Touch?

Our player is drawn as an oval and the obstacle as a rectangle, but checking whether an oval and a rectangle precisely overlap is fiddly maths. Almost every 2D game cheats: it draws an invisible rectangle — a bounding box — around each entity, and just checks whether those two rectangles overlap.

Analogy: imagine each entity casts a rectangular shadow straight down onto the floor, regardless of its actual shape. Instead of comparing the complicated shapes themselves, we just check whether the two shadows overlap. It's not perfectly precise — a bit of empty space at an oval's corners might count as a "hit" — but it's fast, simple, and good enough for almost every game.

Example 4: Obstacles Enter the Scene

Before we can collide with anything, we need something to collide with. Let's bring the Obstacle entity back from Module 4 and get it scrolling — no collision detection yet, just movement and scoring.

Add an Obstacle field, created in initState() just like the player, plus a getter back to the score-tracking GameSession from Module 3: 

  late Obstacle _obstacle;

  GameSession get _session => widget.session;

  @override
  void initState() {
    super.initState();
    _player = Player(x: 40, y: gameHeight - 50);
    _obstacle = Obstacle(x: gameWidth);
    _ticker = createTicker(_onTick)..start();
  }

Then add scrolling and recycling to the end of _updatePhysics(): the obstacle slides left every tick, and once it's fully off-screen, it's recycled back to the right edge and counts as a point survived: 

    _obstacle.x -= 3;
    if (_obstacle.x + _obstacle.width < 0) {
      _obstacle.x = gameWidth;
      _session.addPoint();
    }
  }

Finally, add the obstacle and a score readout to the Stack in build(). Order matters here: the obstacle is listed before the player, so it sits on a lower "sheet" and the player stays clearly visible on top of it:

Example 5: Detect Collisions and End the Game

Flutter's Rect class has the overlap check built in: rectA.overlaps(rectB) returns true if the two rectangles share any space at all. Add a flag for whether the game has ended, plus the check itself as its own method: 

  bool _isGameOver = false;

  bool _checkCollision() {
    final playerRect = Rect.fromLTWH(_player.x, _player.y, _player.size, _player.size);
    final obstacleRect = Rect.fromLTWH(
      _obstacle.x,
      gameHeight - _obstacle.height,
      _obstacle.width,
      _obstacle.height,
    );
    return playerRect.overlaps(obstacleRect);
  }

Next, call it at the end of _updatePhysics(), and guard _onTick and _jump so nothing keeps moving once the game is over: 

    if (_checkCollision()) {
      _isGameOver = true;
      _session.loseLife();
      _ticker.stop();
    }
  }

  void _onTick(Duration elapsed) {
    if (_isGameOver) return;
    setState(_updatePhysics);
  }

  void _jump() {
    if (_isGameOver) return;
    setState(() {
      _velocityY = jumpVelocity;
    });
  }

Last piece: a "Game Over" overlay, added to the Stack in build() only when _isGameOver is true, with the final score and a button back to the menu:

That's a complete game: jump the player over the scrolling obstacle, and the moment you miss, the loop stops itself and shows your score. This final file is also what you'll find in the "Full main.dart" block at the end of this module.

Recap

  • Built a continuous game loop using Ticker and SingleTickerProviderStateMixin, one method at a time
  • Applied gravity as speed that accumulates each tick, in its own _updatePhysics() function
  • Added a jump as an instant burst of upward velocity, in its own _jump() function
  • Scrolled and recycled an obstacle, scoring a point each time it's survived
  • Detected collisions using bounding-box Rect.overlaps(), in its own _checkCollision() function
  • Ended the game and showed a Game Over overlay tied back to GameSession

/// Holds the game's data and rules — no widgets, no UI, just logic.
class GameSession {
  int _score = 0;
  int _lives = 3;

  int get score => _score;
  int get lives => _lives;
  bool get isGameOver => _lives <= 0;

  void addPoint() {
    _score++;
  }

  void loseLife() {
    if (_lives > 0) {
      _lives--;
    }
  }
}

class _GameScreenState extends State
    with SingleTickerProviderStateMixin {
  static const double gameWidth = 360;
  static const double gameHeight = 520;
  static const double gravity = 0.6;
  static const double jumpVelocity = -12;

  late final Ticker _ticker;
  late Player _player;
  late Obstacle _obstacle;
  double _velocityY = 0;
  bool _isGameOver = false;

  GameSession get _session => widget.session;

  @override
  void initState() {
    super.initState();
    _player = Player(x: 40, y: gameHeight - 50);
    _obstacle = Obstacle(x: gameWidth);
    _ticker = createTicker(_onTick)..start();
  }

  @override
  void dispose() {
    _ticker.dispose();
    super.dispose();
  }

  void _onTick(Duration elapsed) {
    if (_isGameOver) return;
    setState(_updatePhysics);
  }

  void _updatePhysics() {
    _velocityY += gravity;
    _player.y += _velocityY;

    final groundY = gameHeight - _player.size;
    if (_player.y > groundY) {
      _player.y = groundY;
      _velocityY = 0;
    }
    if (_player.y < 0) {
      _player.y = 0;
      _velocityY = 0;
    }

    _obstacle.x -= 3;
    if (_obstacle.x + _obstacle.width < 0) {
      _obstacle.x = gameWidth;
      _session.addPoint();
    }

    if (_checkCollision()) {
      _isGameOver = true;
      _session.loseLife();
      _ticker.stop();
    }
  }

  bool _checkCollision() {
    final playerRect = Rect.fromLTWH(_player.x, _player.y, _player.size, _player.size);
    final obstacleRect = Rect.fromLTWH(
      _obstacle.x,
      gameHeight - _obstacle.height,
      _obstacle.width,
      _obstacle.height,
    );
    return playerRect.overlaps(obstacleRect);
  }

  void _jump() {
    if (_isGameOver) return;
    setState(() {
      _velocityY = jumpVelocity;
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Game')),
      body: Center(
        child: GestureDetector(
          onTap: _jump,
          child: SizedBox(
            width: gameWidth,
            height: gameHeight,
            child: ClipRect(
              child: Stack(
                children: [
                  const GameBackground(),
                  _obstacle.build(),
                  _player.build(),
                  Positioned(
                    top: 16,
                    left: 16,
                    child: Text(
                      'Score: ${_session.score}',
                      style: const TextStyle(
                        fontSize: 20,
                        color: Colors.white,
                        fontWeight: FontWeight.bold,
                        shadows: [Shadow(blurRadius: 4, color: Colors.black)],
                      ),
                    ),
                  ),
                  if (_isGameOver)
                    Positioned.fill(
                      child: Container(
                        color: Colors.black54,
                        child: Center(
                          child: Column(
                            mainAxisSize: MainAxisSize.min,
                            children: [
                              const Text(
                                'Game Over',
                                style: TextStyle(
                                  fontSize: 32,
                                  color: Colors.white,
                                  fontWeight: FontWeight.bold,
                                ),
                              ),

                              Text(

/// The player character — an entity with a position and a way to draw itself.
class Player {
  double x;
  double y;
  final double size;

  Player({required this.x, required this.y, this.size = 50});

  Widget build() {
    return Positioned(
      left: x,
      top: y,
      child: CustomPaint(
        size: Size(size, size),
        painter: _PlayerPainter(),
      ),
    );
  }
}

class _PlayerPainter extends CustomPainter {
  @override
  void paint(Canvas canvas, Size size) {
    final body = Paint()..color = Colors.orange;
    canvas.drawOval(Rect.fromLTWH(0, 0, size.width, size.height), body);

    final eye = Paint()..color = Colors.black;
    canvas.drawCircle(Offset(size.width * 0.68, size.height * 0.35), 4, eye);
  }

  @override
  bool shouldRepaint(covariant CustomPainter oldDelegate) => false;
}

/// An obstacle the player has to avoid — same entity pattern as Player.
class Obstacle {
  double x;
  final double width;
  final double height;

  Obstacle({required this.x, this.width = 40, this.height = 140});

  Widget build() {
    return Positioned(
      left: x,
      bottom: 0,
      child: CustomPaint(
        size: Size(width, height),
        painter: _ObstaclePainter(),
      ),
    );
  }
}

class _ObstaclePainter extends CustomPainter {
  @override
  void paint(Canvas canvas, Size size) {
    final paint = Paint()..color = Colors.green.shade700;
    canvas.drawRect(Rect.fromLTWH(0, 0, size.width, size.height), paint);
  }

  @override
  bool shouldRepaint(covariant CustomPainter oldDelegate) => false;
}
