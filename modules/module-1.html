MODULE 1 OF 5

Environment Setup

Every game needs a workshop before it needs a game. In this module we're going to install the tools, poke around a real Flutter project, and figure out what all those folders and files actually do. By the end, you'll have a working Flutter setup and you'll understand the map before you start exploring the territory.

1. What You're Actually Installing

Flutter apps are written in a language called Dart. Think of Dart as the language you'll be speaking, and Flutter as a massive box of pre-built LEGO pieces (buttons, text, images, layouts) that you snap together using that language.

To write and run Flutter apps on your own computer, you need two things:

  • The Flutter SDK — the actual toolbox: the compiler, the pre-built LEGO pieces, and the command-line tools that turn your code into a real app.
  • Android Studio — the workshop you do the building in. It's an IDE (a fancy code editor) with a virtual Android phone built in, so you can test your app without owning a physical device.

Analogy: if Dart is the language you speak and Flutter is your box of LEGO bricks, Android Studio is the table you build on — and the Flutter SDK is what turns your finished LEGO model into something you can actually press "play" on.

2. Install Android Studio

Head to the official Android Studio download page and grab the installer for your operating system (Windows, macOS, or Linux).

  1. Run the installer and accept the default options — they're fine for now.
  2. When it opens for the first time, let it download the Android SDK components it asks for. This can take a while, so it's a good tea-break moment.
  3. Once it's done, you should land on the Android Studio "Welcome" screen.
[Insert screenshot of the Android Studio 'Welcome' screen here]

3. Install the Flutter SDK

Next, grab the Flutter SDK itself from flutter.dev. Pick your operating system and follow their install steps — it's usually a case of downloading a zip file and unpacking it somewhere sensible, like C:\src\flutter on Windows or ~/development/flutter on macOS/Linux.

Don't skip this bit: you need to add the Flutter bin folder to your system's PATH, so your computer knows where to find the flutter command from any terminal window. The install guide above walks through exactly how to do this for your OS.

4. Run Flutter Doctor

Flutter ships with a built-in health check called flutter doctor. Open a terminal (Command Prompt, PowerShell, or Terminal) and type: 

flutter doctor

This scans your system and tells you exactly what's missing — a bit like a mechanic running diagnostics on a car before a road trip. Don't worry if you see a few red crosses the first time; it usually points you straight at what to fix (like accepting Android licenses, which it'll also give you the exact command for).

[Insert screenshot of a mostly-green 'flutter doctor' output here]

5. Install the Flutter and Dart Plugins

Back in Android Studio, you need two plugins so it understands Dart and Flutter code:

  1. Go to Settings/Preferences > Plugins.
  2. Search for "Flutter" and click install. This automatically pulls in the Dart plugin too.
  3. Restart Android Studio when prompted.

6. Create Your First Project

From the Android Studio Welcome screen, choose New Flutter Project, point it at your Flutter SDK folder if asked, give your project a name (lowercase, underscores instead of spaces — e.g. side_scroller_game), and let it generate the starter files.

7. Tour the Project Structure

Android Studio just generated a whole pile of folders. Most of them, you can ignore for months. Here's what actually matters right now:

Analogy: think of your project like a house. lib/ is the living room — it's where you'll spend basically all your time. android/ and ios/ are the foundations and plumbing — necessary, but you almost never need to open them up. pubspec.yaml is the house's official paperwork: what it's called, what's inside it, and what it depends on.

  • lib/ — where all your Dart code lives. lib/main.dart is the front door: the first file that runs.
  • android/ and ios/ — native platform-specific configuration. You'll rarely touch these in this course.
  • test/ — where automated tests live. We won't dwell on this, but it's good to know it's there.
  • pubspec.yaml — your project's ID card and shopping list, covered next.
  • pubspec.lock — an auto-generated file that records the exact versions of everything installed. You won't edit this by hand.

8. Understanding pubspec.yaml

Open pubspec.yaml in your new project. It'll look something like this: 

name: side_scroller_game
description: "A side-scrolling game built in Flutter."
publish_to: 'none'
version: 1.0.0+1

environment:
  sdk: '>=3.0.0 <4.0.0'

dependencies:
  flutter:
    sdk: flutter
  cupertino_icons: ^1.0.2

dev_dependencies:
  flutter_test:
    sdk: flutter
  flutter_lints: ^2.0.0

flutter:
  uses-material-design: true

Analogy: think of pubspec.yaml as a recipe card. The name and description are the dish's title. The dependencies section is your ingredients list — every external package (pre-written code someone else built, like an image loader or an audio player) that your app needs to work. Later in this series, when we add things like image or audio packages, this is the file we'll be editing.

9. Try It Yourself: Your First Live Code

For the rest of this course, we're actually going to write and run our code in DartPad — a version of Flutter that runs entirely in your browser, no install required. It's perfect for quick experiments and for following along on any computer. The live panel on the right is a real, running DartPad — try hitting its Run button.

This might seem strange after everything you just installed! But it's deliberate: knowing what's happening on your own machine (what you just did above) means you'll actually understand what DartPad is doing behind the scenes for you.

New File 
import 'package:flutter/material.dart';

void main() {
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Hello Flutter',
      theme: ThemeData(
        primarySwatch: Colors.blue,
        useMaterial3: true,
      ),
      home: const Scaffold(
        body: Center(
          child: Text(
            'Hello, Game Dev!',
            style: TextStyle(fontSize: 32, fontWeight: FontWeight.bold),
          ),
        ),
      ),
    );
  }
}

Notice what's happening: runApp() is the very first line of Dart that executes — it's the "front door" moment we talked about in lib/main.dart. Everything else is just widgets, stacked inside each other like nested boxes, describing what should appear on screen. We'll pull this apart properly in Module 2.
